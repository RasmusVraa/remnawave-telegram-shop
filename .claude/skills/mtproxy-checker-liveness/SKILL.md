# mtproxy-checker-liveness — доступен ли сервер из РФ и не режет ли его ТСПУ

Главный вопрос — **доступно ли жителям РФ**. Зарубежная проверка нужна только как контроль: отличить блокировку РКН от упавшего сервера.

## Запуск

Скрипт `check.py` лежит рядом с этим файлом, нужен только Python 3 без зависимостей. Путь ниже — для копии в `~/.claude/skills`; в проекте запускай `.claude/skills/mtproxy-checker-liveness/check.py`.

```bash
python ~/.claude/skills/mtproxy-checker-liveness/check.py proxy.example.com:2443
python ~/.claude/skills/mtproxy-checker-liveness/check.py 203.0.113.10:443 198.51.100.7:22 --ru 8
python ~/.claude/skills/mtproxy-checker-liveness/check.py --file servers.txt --ru 7
```

- Цель — `host:port` (домен или IP). Без порта берётся `--port` (443).
- `--file` — строки `имя host:port` или `host:port`, `#` — комментарий.
- `--ru N` — зондов из РФ (по умолчанию 8: половина домашние провайдеры, половина датацентры).
- `--no-foreign` — без зарубежного контроля, `--json` — сырые итоги.
- Домен резолвится локально, проверяется IP — так DNS-проблемы в РФ не смешиваются с блокировкой.

**Какой порт проверять.** ТСПУ режет TCP до IP целиком, поэтому для оценки «живой ли IP для РФ» подходит любой заведомо открытый порт (SSH 22/2228). Для конкретного прокси — его порт.

**Список серверов.** Если пользователь держит сессии в MobaXterm — они в `%APPDATA%\MobaXterm\MobaXterm.ini`, секции `[Bookmarks*]`, формат `имя=#109#0%host%port%user%...`. Пароли из `[Passwords]` не читать и не выводить. Готовый список с адресами серверов не сохраняй в репозиторий — только во временную папку. Перед массовой проверкой отсей российские IP (`curl -s ipinfo.io/<ip>/json`) — ТСПУ их не касается — и спроси пользователя, какие исключить.

## Квота Globalping

Без токена — 250 проб в час на IP (каждый зонд = 1 проба). Цена одной цели: `ru + 3` (TCP РФ + зарубеж) и ещё до 6, если TCP из РФ плохой (ping). Остаток: `curl -s https://api.globalping.io/v1/limits`. На большие списки уменьшай `--ru` или задай `GLOBALPING_TOKEN` (бесплатный токен на globalping.io — 500/час). При 429 скрипт допечатает то, что успел проверить.

## Как читать вердикт

| РФ TCP | Зарубеж TCP | РФ ping | Вердикт | Значит |
|---|---|---|---|---|
| ≥70% | — | — | OK | Жителям РФ доступно |
| ≤30% | ok | ≥70% | ТСПУ РЕЖЕТ TCP | Классика блокировки IP: ping проходит, TCP-SYN дропается |
| ≤30% | ok | плохо | ЗАБЛОКИРОВАН | Полная блокировка IP (или на сервере закрыт ICMP) |
| 30–70% | ok | — | ЧАСТИЧНО | Блок раскатывается по провайдерам или зависит от сети |
| любое | 0% | — | НЕДОСТУПЕН ОТОВСЮДУ | Проблема на сервере (лёг, порт закрыт, файрвол, хостер), не РКН |

Важнее всего строки «дом» — это домашние/мобильные провайдеры, через которые ходят клиенты. Датацентровые зонды РФ (Timeweb, Yandex.Cloud, Selectel) иногда видят другую картину.

## Подтверждение на самом сервере (если есть SSH)

Пока идёт проверка из РФ, на сервере:

```bash
ss -tlnp | grep <порт>                  # сервис слушает
nc -zv -w5 $(curl -4s ifconfig.me) <порт> # доступен по публичному IP
tcpdump -ni any 'tcp port <порт> and tcp[tcpflags] & tcp-syn != 0'
```

- SYN с российских IP не приходят вовсе → режут по пути (ТСПУ).
- SYN приходят, SYN-ACK уходит, а у зонда таймаут → режут обратный путь (тоже ТСПУ).
- SYN приходят, SYN-ACK нет → локальный файрвол/сервис.

## Ограничения

- Проверка ловит блокировку на этапе TCP-соединения. «Заморозку» соединения после ~16–20 КБ трафика к зарубежным хостингам TCP-проверка не видит — если TCP OK, а клиенты жалуются на зависания, проверяй реальным клиентом из РФ.
- Блокировки раскатываются по провайдерам постепенно: OK сегодня не гарантирует OK завтра. Для постоянного наблюдения — автопроверка в боте mtproxyL.
- Блокируют обычно конкретный IP, а не всю подсеть хостера — соседние IP того же хостера могут быть живы (проверено на практике: один IP хостера под блоком, два соседних — OK). Поэтому первым делом стоит попросить у хостера новый IP.
