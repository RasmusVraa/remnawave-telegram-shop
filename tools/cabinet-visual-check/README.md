# Визуальная проверка кабинета

Снимает страницы собранного кабинета в браузере, подставляя вместо API файл с
данными. Нужен, чтобы посмотреть свою вёрстку глазами до того, как её увидит
кто-то ещё: ни база, ни бот, ни авторизация для этого не требуются.

## Зачем

Сверить экран с макетом по коду нельзя — совпадение структуры ещё не значит
совпадения вида. Отступы, плотность, обрезанные подписи, нечитаемое активное
состояние, поплывшая на телефоне сетка видны только на картинке.

## Как запускать

```bash
cd web/cabinet && npm run build && cd ../..

node tools/cabinet-visual-check/capture.mjs \
  --route /cabinet/admin/stats \
  --fixtures tools/cabinet-visual-check/fixtures/admin-stats.json \
  --out .tmp/cabinet-shots \
  --viewport 1440x1100 --viewport 390x900 \
  --step 'Деньги' --step 'Пользователи' --step 'Механики'
```

Снимки лягут в `--out` с именами `<тема>-<ширина>-<шаг>.png`.

## Скриншоты к релизу

`release-shots.mjs` — те же снимки, но с жёлтой рамкой и подписью на изменённом
месте; складываются в `release-screenshots/`, откуда `tools/release` отправляет
их альбомом к посту. Сценарии внутри — под конкретный релиз, порядок — в скилле
релиза (`.claude/skills/release-github-telegram/SKILL.md`).

## Ключи

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `--route` | `/cabinet/admin/stats` | Страница кабинета |
| `--dist` | `internal/cabinet/web/dist` | Каталог сборки |
| `--fixtures` | — | JSON: путь API → ответ |
| `--out` | `.tmp/cabinet-shots` | Куда класть снимки |
| `--viewport` | `1440x1100`, `390x900` | Можно повторять |
| `--step` | — | Кликнуть вкладку/кнопку по названию и снять ещё кадр |
| `--element` | — | Снять только этот селектор вместо всей страницы |
| `--theme` | `dark` | `dark`, `light` или `dark,light` |
| `--locale` / `--timezone` | `ru-RU` / `Europe/Moscow` | Влияют на форматы чисел и дат |
| `--settle` | `1800` | Пауза после загрузки, мс |
| `--port` | `5599` | Порт локальной статики |

## Фикстуры

Обычный JSON: ключ — путь после `/cabinet/api`, значение — тело ответа.

```json
{
  "/admin/stats": { "total_customers": 3418 },
  "/admin/stats/insights": { "funnel": { "registered": 184 } }
}
```

`/auth/refresh`, `/me` (с `is_admin: true`) и `/admin/bootstrap` подставляются
сами — без них кабинет уводит на логин. Фикстура может их переопределить.
Путь, которого нет в файле, отвечает `{}`: экран не должен падать из-за
метрики, которой в фикстуре просто нет.

Данные в фикстурах выдуманные. Настоящие выгрузки сюда класть нельзя.

## Что стоит знать

**Пустой график на полностраничном снимке — артефакт съёмки, а не баг.**
Recharts переизмеряет ширину, когда Playwright растягивает страницу под
`fullPage`, и иногда попадает в кадр между перерисовками. Проверяйте такой
случай точечно: `--element '.recharts-responsive-container'`.

**Ошибки в консоли печатаются в конце прогона.** Сырой ключ вроде
`admin.stats.someKey` на картинке означает отсутствующую строку локализации —
это ловится глазами, а не типами.

## Требования

Playwright с браузером. Он прописан в `package.json` этого каталога, а не в
кабинете: в сборку фронтенда и в Docker-образ он не попадает. Один раз после
клона:

```bash
cd tools/cabinet-visual-check && npm ci && npx playwright install chromium
```

В Git Bash на Windows аргумент вида `/cabinet/...` MSYS разворачивает в путь
установки Git. Скрипт это чинит сам, но если маршрут ведёт себя странно —
`MSYS_NO_PATHCONV=1` перед командой.
