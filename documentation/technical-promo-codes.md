# Служебные промокоды

Часть функций хранит скидки клиента в таблице `customer_pending_discount`, у которой есть внешний ключ на `promo_code`. Чтобы его не нарушать, под такие функции в `promo_code` лежат «якорные» промокоды. Это не настоящие промокоды: их нельзя ввести, они неактивны и существуют только как привязка скидки.

| Код | Для чего | Миграция |
|-----|----------|----------|
| `__CABINET_FORTUNE__` | Скидки 3% и 5%, выигранные на колесе фортуны (одна оплата) | `000033` |
| `__LIFECYCLE_WINBACK__` | Скидка «возвращайся» (win-back) в уведомлениях жизненного цикла | `000035` |

## Правило

**Любой код, начинающийся с `__`, служебный и не показывается в админке промокодов**: ни в списке, ни в счётчиках («всего / активных / неактивных»), ни в топе статистики.

- Скрытие делается в `internal/database/promo.go` по префиксу `TechnicalPromoPrefix`, а не по списку имён. Новому служебному коду достаточно называться `__ИМЯ__`, и он скроется сам.
- Создать код с `__` в начале через админку нельзя (проверка в `validateCreatePromo`), так что обычный промокод под фильтр не попадёт.
- Если появится новая функция, которой нужен якорь, заведите его миграцией с именем `__ИМЯ__`, не добавляйте исключение в запросы списка. Новый запрос к `promo_code`, который показывает данные админу, должен фильтровать по `code NOT LIKE '\_\_%'` (константа `notTechnicalPromo`).
