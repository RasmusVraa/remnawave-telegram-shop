# Статус серверов

Страница, на которой клиенты видят, какие серверы сейчас работают. Она есть в четырёх местах:

| Где | Что видит пользователь |
|-----|------------------------|
| `/status` на вашем домене, без входа | Публичная страница: карта, таблица серверов, история последних 30 замеров |
| «Статус серверов» в меню ☰ кабинета (`/cabinet/status`) | Карточки по серверам, удобные на телефоне |
| Вкладка «Статус» на странице «Поддержка» | Короткая сводка: цветная строка и 3–5 серверов, сначала проблемные |
| Кнопка «Статус серверов» на главной | Одно из быстрых действий на местах 3 и 4 (по умолчанию выключено) |

Пока в списке нет ни одного включённого сервера, всё это скрыто: пункт меню, кнопка, вкладка и ссылка в подвале лендинга пропадают, а `/status` ведёт на главную.

> **Откуда это.** Идея страницы, карта и первый вариант замера взяты из форка
> [RasmusVraa/remnawave-telegram-shop](https://github.com/RasmusVraa/remnawave-telegram-shop). Мы переписали хранение,
> логику статуса и админку, поэтому поведение отличается от форка (см. «Чем отличается от форка» ниже).

## Быстрый старт

1. Админка кабинета → **Статус серверов** → **Добавить сервер**.
2. Выберите сервер из панели Remnawave (название, страна и адрес подставятся сами) или нажмите «Добавить вручную».
3. Проверьте название, страну и адрес, нажмите «Готово», затем **Сохранить** в нижней панели.
4. Первый замер появится через несколько минут. Ускорить можно кнопкой «Проверить сейчас».

Ключи внешних сервисов необязательны, без них проверка тоже работает (см. «Откуда берутся данные»).

## Типы серверов

| Тип | Для чего | Что проверяется |
|-----|----------|-----------------|
| **Обычный сервер** | Нода Remnawave, к которой пользователи подключаются напрямую | TCP-пинг адреса из мира и из России (Globalping) |
| **Обход (каскад)** | Вход в России и зарубежный выход, работает при белых списках операторов | Тот же пинг + проверка операторов с белыми списками (Latency Lab); статус — по операторам |

У строки несколько полей:

- **Название, страна, подпись.** Страна выбирается из списка с флагами. Подпись под названием необязательна: если вы её не задали, под названием ничего нет.
- **Адрес** — публичный IP или домен, который видно из интернета. Пользователям он не показывается.
- **Порт** — TCP-порт, на который подключаются клиенты (обычно 443, он же по умолчанию). Если вписать адрес как `host:8443`, порт возьмётся из адреса.
- **Хост для проверки** (у обхода) — это не адрес самой ноды, а тот хост, который пользователи открывают через белые списки, например домен Яндекса. Если здесь остался адрес ноды из панели, окно сервера предупредит.
- **Сервер в панели** — по нему страница узнаёт, подключена ли нода. Если не выбран, нода ищется по адресу.
- **Зарубежный выход** (у обхода) — узел панели, на который выходит каскад. Если выход не работает, весь сервер показывается неработающим, даже если вход отвечает.
- **Дополнительно:** свой интервал, число проверок из мира и из России, «несколько проверок из одного города», «не отправлять адрес внешним сервисам».

Порядок строк в списке — порядок на странице. Выключатель в строке скрывает сервер, не удаляя его.

## Как считается статус

Итог по серверу собирается из трёх источников: состояние ноды в панели, результаты проверок и (у обхода) состояние зарубежного выхода.

Зонды Globalping делают **TCP-пинг** на порт сервера, а не ICMP. ICMP проходит даже там, где ТСПУ режет TCP до порта VPN, и сервер выглядел бы живым. TCP-пинг — это только установка соединения: он не проверяет, пройдёт ли сам протокол VPN. В логах Xray на ноде будут короткие пустые подключения от зондов, это нормально.

**Обычный сервер.** Главное — проверка из России. `N` — порог из настройки «Сбоев из России до «Частично»» (`STATUS_RU_FAIL_THRESHOLD`, по умолчанию 2).

| Ситуация | Что покажет страница |
|----------|----------------------|
| Нода в панели работает, из России не ответили меньше `N` зондов, мир отвечает | Работает (один сбой из десяти — обычный шум зондов) |
| Из России не ответили `N` и больше, но больше половины ответило | Частично |
| Из России ответила половина или меньше, один замер | Частично |
| Из России ответила половина или меньше, два замера подряд | Недоступен (даже если мир отвечает: клиентам из России сервер не открывается) |
| Не отвечает зонд из мира | Частично |
| Не ответил ни один зонд, один замер подряд | Частично |
| Не ответил ни один зонд, два замера подряд | Недоступен |
| В панели «не работает», но зонды достучались | Частично (нода могла потерять связь с панелью, но отвечать из интернета) |
| В панели «не работает», проверок ещё нет | Недоступен |
| Зарубежный выход каскада не работает | Недоступен |
| Узел не найден в панели и проверок нет | Нет данных (плашки нет) |

**Обход.** Решают только операторы с белыми списками: мир и датацентры России клиенту на мобильном интернете ничего не говорят. Все операторы ответили — «Работает», не ответил хотя бы один — «Частично», не ответил ни один два полных прохода подряд — «Недоступен». Без ключа Latency Lab обход судится по зондам России, как обычный сервер, но без мира.

Плашка сверху страницы берёт худшее из серверов: есть «Недоступен» — «Часть локаций недоступна» (или «Все локации недоступны»), есть «Частично» — «Часть локаций работает с перебоями», иначе «Все локации на связи». Так же считает сводка во вкладке «Статус» в поддержке.

Если замер старше 6 часов или внешние проверки выключены, прошлый провал на статус не влияет, дальше работает только панель.

На карточке плашка «Частично» или «Недоступен» и подсветка есть только у проблемных серверов. У работающего сервера плашки нет. В колонках «Из мира» и «Из России» показано, что ответили зонды в последнем замере: итог может от них отличаться, потому что учитывает ещё и панель и прошлый замер. Колонка «Из России» красится по тому же порогу: меньше `N` сбоев — зелёная, больше половины ответило — оранжевая «С перебоями», половина и меньше — красная.

## Оповещения о сбоях

Бот пишет админу, когда сервер начинает сбоить и когда восстанавливается. Куда — вид «Статус серверов» в «Настройки бота → Уведомления → Оповещения админу» (по умолчанию личка `ADMIN_TELEGRAM_ID`).

| Причина | Когда приходит «сбой» | Когда «восстановился» |
|---------|----------------------|-----------------------|
| Из России (обычный сервер; обход без ключа Latency Lab) | не ответили `N` зондов и больше два замера подряд | первый замер, где сбоев меньше `N` |
| Из мира (только обычный сервер, выключается `STATUS_ALERT_WORLD`) | мир не ответил два замера подряд | первый замер, где мир ответил |
| Операторы (обход с ключом Latency Lab) | хотя бы один оператор не ответил в двух полных проходах подряд | первый полный проход, где ответили все |
| Реестр РКН (только обычный сервер, выключается `STATUS_ALERT_REGISTRY`) | адрес найден в списках блокировок два ответа подряд | первый ответ, где адрес не найден |

`N` — тот же порог «Сбоев из России до «Частично»». Причины у сервера независимые. За проход проверок приходит одно сообщение со всеми серверами: кто сбоит и кто не ответил (до пяти зондов или операторов), ниже — кто восстановился и сколько длился сбой. Напоминаний, пока сбой висит, нет. При сбое интервал проверок падает до 10 минут, поэтому оповещение приходит примерно через 10–20 минут.

Тревога хранится вместе с замером, после перезапуска бота повторно не приходит. Сервер выключили или убрали из списка во время сбоя — тревога забывается молча. Пока Globalping или Latency Lab на паузе после 429 или проверки выключены, оповещений нет.

## Реестр РКН

У каждого обычного сервера в админке третий значок «РКН». Зелёный: адрес не числится в реестре Роскомнадзора и в диапазонах заблокированных CDN. Красный: числится, из России такой адрес может не открываться, даже если пинг из мира идёт. Серый: проверки ещё не было, сервис не ответил или внешние проверки у строки выключены. Значок видит только админ, на публичной странице его нет. У строк «Обход» значка нет: там адрес — хост из белого списка, а не адрес сервера.

Проверка идёт через открытый API [cheburcheck.ru](https://cheburcheck.ru) (`GET /api/v1/check`), ключ не нужен. Раз в 30 минут бот спрашивает адрес каждого включённого обычного сервера. Если адрес найден, повторная проверка через 10 минут: тревога открывается только после двух находок подряд. Это проверка по спискам, а не пинг: она не заметит блокировку по SNI или DPI, если адреса нет в списках, и не заметит обрыв на лету.

Списки у сервиса обновляются так: домены реестра раз в 30 минут, подсети раз в час, диапазоны CDN раз в 12 часов. Когда списки обновлены в последний раз и сколько серверов сейчас числятся в них, видно в карточке «Реестр РКН» в блоке «Откуда берутся данные». Ответ 429 ставит проверку на паузу до времени из `Retry-After`. Если сервис недоступен, значок остаётся серым и тревоги нет.

Оповещение приходит тем же видом «Статус серверов» и в том же сообщении, что и остальные сбои. Адрес сервера уходит только в cheburcheck, в замер и на публичную страницу он не попадает. Строки с галочкой «Без внешних проверок» не проверяются.

## Откуда берутся данные

| Сервис | Что делает | Ключ в `.env` | Лимит |
|--------|-----------|---------------|-------|
| [Globalping](https://dash.globalping.io) | Пингует адрес из мира и из России | `GLOBALPING_TOKEN` (необязательно) | 250 проверок в час на IP, с ключом 500 |
| [Latency Lab](https://console.latencylab.ru) | Проверяет адрес модемами операторов с белыми списками | `LATENCYLAB_TOKEN` (нужен для обхода) | Остаток не отдаёт, виден в их кабинете |
| [Cheburcheck](https://cheburcheck.ru) | Смотрит, числится ли адрес в реестре РКН и в диапазонах заблокированных CDN | не нужен | Раз в 30 минут на сервер, при 429 пауза |

Каждая проверка одного зонда в Globalping — одна единица лимита. Админка показывает, сколько уходит у вашего списка, и предупреждает, если лимита мало. Если сервис ответил «слишком много запросов» (429), проверки встают на паузу до времени из ответа, и админка это показывает.

Как подключить ключи: получите ключ, добавьте в `.env` строки `GLOBALPING_TOKEN=…` и `LATENCYLAB_TOKEN=…`, перезапустите бота. Та же инструкция есть в админке, в окне «Как подключить».

### Умолчания

Если ничего не менять: **1** проверка из мира, **10** из России, замер **раз в 60 минут**. При таких настройках один сервер тратит около 11 единиц лимита Globalping в час. Значения меняются в админке, раздел «Страница → Дополнительно», у конкретного сервера можно задать свои.

### Что уходит наружу

Адрес каждого сервера (у обхода — хост для проверки) передаётся Globalping и Latency Lab: они сами стучатся на него. Публичный JSON страницы адресов и идентификаторов узлов не содержит. Если не хотите отдавать адрес сервера внешним сервисам, включите у него «Не отправлять адрес внешним сервисам»: тогда статус берётся только из панели, а полоски последних 30 замеров у такого сервера не будет. Выбранный сервер в панели при этом обязателен, иначе статуса не будет вовсе.

Чтобы отключить внешние проверки для всех серверов сразу, выключите «Проверять доступность» в блоке «Страница».

Если внешние сервисы недоступны, ложных «Недоступен» не появится: пока замеров нет, страница показывает последние данные, а через 6 часов считает статус по панели.

## Настройки страницы

Блок «Страница» в админке:

| Настройка | Что делает |
|-----------|-----------|
| Проверять доступность (`STATUS_PROBES_ENABLED`) | Выключено: только статус из панели |
| Показывать карту (`STATUS_SHOW_MAP`) | Карта на публичной странице |
| Заголовок и подзаголовок публичной страницы (`STATUS_PAGE_TITLE`, `STATUS_PAGE_LEAD`) | Только для `/status`, в кабинете у раздела свой заголовок. Пусто — стандартный текст |
| Проверок из мира и из России, раз в … мин | Общие значения для серверов, у которых нет своих |

Все они меняются без перезапуска. Полный список переменных — в [env.md](../env.md#статус-серверов).

## Где хранится

- **Список серверов** — настройка `status_probe_targets` в таблице `bot_runtime_settings` (до 24 строк).
- **Замеры и история** — таблицы `status_probe_run` (по строке на замер, последние 30 на сервер; миграция 62) и `status_probe_sample` (последний замер, миграция 59). Один столбик полоски — один замер, интервал между замерами задаёт «Раз в, мин» в админке. Цвет столбика: зелёный — прошли все проверки замера, оранжевый — часть не прошла, но ответила больше половины, красный — ответила половина или меньше. Прежняя таблица `status_probe_day` (итог по дням) остаётся в базе нетронутой и не используется: историю по дням на замеры не разложить.
- В базу не попадают адреса серверов.

## Чем отличается от форка

- Замеры и история лежат в таблицах, а не одним JSON, который переписывался после каждой проверки.
- Тип «Обычный / Обход», привязка к узлу панели по идентификатору, зарубежный выход каскада, «добавить из панели».
- «Недоступен» только после двух замеров подряд, итог учитывает панель, зонды и выход каскада.
- Опция «не отправлять адрес внешним сервисам», оценка расхода лимита Globalping и пауза после 429 в админке.
- Ограничение частоты запросов и короткий кэш на публичной странице.
- Подсветка и плашка только у проблемных серверов, живая сводка в поддержке, кнопка быстрых действий на главной.
- Новая админка: список строк с окном правки, выбор страны с флагами, окно «Как подключить ключи».
- Страница скрывается, пока нет серверов.
